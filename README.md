# 서울 청약 대시보드

**웹사이트 → https://hhkim17.github.io/seoul-cheongyak/**

서울의 청약 공고를 제도별 **코너**로 나눠 보여주고, 일정(D-day)·분양가·임대조건·전용면적·경쟁률·당첨 커트라인을
한 화면에 모읍니다. 내 조건(가점·예산·면적·특별공급 자격·관심 자치구)에 맞춰 자동으로 순위를 매깁니다.

|---|---|---|

| 🤝 공공지원 민간임대 | 청년·신혼부부 우선공급 있는 민간임대 | 청약홈 |

### SH(서울주택도시공사)는 왜 없나

SH는 실시간 공고 Open API를 공개하지 않습니다. 공공데이터포털에 있는 SH 데이터는 「자치구별 임대주택 현황」 같은
정적 파일뿐이고, 장기전세·행복주택 등 실제 공고는 [SH 인터넷청약시스템](https://www.i-sh.co.kr/)과
[서울주거포털](https://housing.seoul.go.kr/site/main/sh/publicLease/list) 게시판에만 올라옵니다.
HUG 든든전세도 마찬가지로 별도 공고 API가 없습니다. 두 곳은 직접 확인하셔야 합니다.

## 어떻게 돌아가나

- **웹사이트** — GitHub Actions가 30분마다 공고를 다시 받아 `docs/` 를 새로 만들고, GitHub Pages가 그걸 서빙합니다.
  서버가 없으므로 인증키도 노출되지 않습니다(Actions 시크릿에만 있음).
- **로컬 실행** — `./start.sh` 로 실시간 프록시 서버를 띄우면 캐시 없이 바로바로 조회됩니다.

## 1. 인증키 발급 (최초 1회)

공공데이터포털 인증키는 **계정당 하나**지만, **API마다 활용신청을 따로** 해야 합니다.
아래 링크에서 각각 「활용신청」을 누르면 됩니다. 개발계정은 전부 **자동승인**이고 무료입니다.
(신청 직후 반영까지 최대 1시간 걸릴 수 있습니다.)

| # | API | 이걸 신청하면 나오는 것 | 없으면 |
|---|---|---|---|
| 1 | [청약홈 분양정보 조회 서비스](https://www.data.go.kr/data/15098547/openapi.do) | 아파트·무순위·오피스텔·공공지원임대 공고, 주택형·분양가 | **앱이 아예 안 돕니다** |
| 2 | [청약홈 청약접수 경쟁률 및 특별공급 신청현황 조회 서비스](https://www.data.go.kr/data/15098905/openapi.do) | 경쟁률, 당첨가점(최저/평균/최고), 특별공급 신청현황 | 경쟁률·가점 칸이 빕니다 |
| 3 | [LH 분양임대공고문 조회 서비스](https://www.data.go.kr/data/15058530/openapi.do) | 행복주택·국민임대·영구임대·매입/전세임대 공고 | 🏠 공공임대주택 코너가 빕니다 |
| 4 | [LH 분양임대공고별 공급정보 조회 서비스](https://www.data.go.kr/data/15056765/openapi.do) | LH 공고의 주택형·세대수·임대조건 | LH 공고에 세대수·임대료가 안 붙습니다 |

| 6 | [마이홈포털 공공주택 모집공고 조회 서비스](https://www.data.go.kr/data/15108420/openapi.do) | **SH·지방공사 포함** 공공임대·공공분양 통합 공고 | SH 물량이 안 들어옵니다 |

신청 후 [마이페이지 › 인증키](https://www.data.go.kr/iim/api/selectAPIAcountView.do)에서 **일반 인증키** 를 복사해 둡니다.

앱을 열면 상단에 **「데이터 연결 상태」** 패널이 있어, 6개 중 무엇이 붙었고 무엇이 안 붙었는지와
각각의 활용신청 링크를 바로 볼 수 있습니다.

### SH·HUG는 Open API가 없어 게시판을 직접 읽습니다

SH(서울주택도시공사)와 HUG(주택도시보증공사)는 실시간 공고 Open API를 공개하지 않습니다.
그래서 두 곳은 **공개 공고 게시판을 직접 수집**합니다(`scrape.mjs`). 두 사이트 모두 `robots.txt`에서
해당 목록 페이지 수집을 허용하고 있고, 요청 사이에 간격을 둡니다.

| 대상 | 읽는 곳 | 들어오는 것 |
|---|---|---|
| SH | [공고 및 공지 게시판](https://www.i-sh.co.kr/main/lay2/program/S1T1637C1639/www/brd/m_247/list.do) | 장기전세·청년안심주택·행복주택·매입임대·미리내집·사회주택 등 |
| HUG | [든든전세 모집공고](https://www.khug.or.kr/jeonse/web/s07/s070102.jsp) | 든든전세주택 모집 물량(시군구·주소·전용면적·임대보증금) |

**게시판 목록에는 접수기간이 없습니다.** 없는 일정을 지어내지 않고 「공고 게시 — 일정은 원문 확인」
상태로 표시하며, 카드를 누르면 공고 원문으로 바로 갈 수 있습니다.
게시판 구조가 바뀌면 수집이 실패할 수 있고, 그때는 「데이터 연결 상태」에 그대로 표시됩니다.

여기에 더해 국토교통부 **마이홈포털**(6번)이 LH·SH·지방공사 공고를 통합해 제공하므로, 활용신청하시면
SH 물량이 API 경로로도 함께 들어옵니다.

## 2. 실행

```bash
cd ~/Desktop/seoul-cheongyak
./start.sh
```

브라우저에서 http://localhost:5173 이 열립니다.

인증키를 주는 방법은 세 가지이고, 아무거나 하나면 됩니다.

1. **첫 화면에 붙여넣기** — 한 번 넣으면 `config.json`에 저장되어 다음부터는 바로 대시보드로 들어갑니다.
2. **파일로 미리 넣기** — `cp config.example.json config.json` 후 키를 채워 넣습니다.
3. **환경변수** — `APPLYHOME_SERVICE_KEY=... node server.mjs`

`config.json`은 `.gitignore`에 들어 있어 커밋되지 않습니다. 인증키는 이 컴퓨터를 벗어나지 않습니다.

### 새 공고 이메일 알림

30분마다 갱신할 때 **직전 스냅샷과 비교해 새로 올라온 공고**를 찾고, `watch.json` 조건에 맞는 것만
메일로 보냅니다. 게시판 수집분은 「당첨자 발표」·「안내」가 섞이므로 **모집공고만** 보냅니다.

조건은 저장소의 [`watch.json`](watch.json)에서 바꿉니다 — 코너, 관심 자치구, 최대 분양가/보증금,
전용면적 범위, 해당 특별공급. 고쳐서 커밋하면 다음 갱신부터 반영됩니다.

받으려면 저장소 시크릿 세 개가 필요합니다(Gmail 기준).

```bash
gh secret set MAIL_USERNAME --body "보내는-지메일@gmail.com"
gh secret set MAIL_PASSWORD --body "앱-비밀번호-16자리"
gh secret set MAIL_TO       --body "받을-메일@example.com"
```

`MAIL_PASSWORD`는 지메일 로그인 비밀번호가 아니라 [Google 계정 › 앱 비밀번호](https://myaccount.google.com/apppasswords)에서
만든 16자리입니다(2단계 인증이 켜져 있어야 나옵니다). 시크릿이 없으면 발송 단계만 조용히 건너뜁니다.

### 코드 자동 동기화

`start.sh`는 서버와 함께 `autosync.mjs`를 띄웁니다. 이 폴더의 파일을 고치면 **8초 뒤 알아서 커밋하고 GitHub에 푸시**합니다.
`public/` 아래를 고쳤으면 푸시 전에 `node build.mjs --assets` 를 돌려 `docs/` 에도 반영하므로,
**코드를 고치면 잠시 뒤 사이트에 그대로 올라갑니다** (데이터는 건드리지 않아 인증키도 필요 없습니다).
`config.json`·`.env`·`cache/`는 감시에서 제외되고, 커밋 직전에 인증키 문자열이 섞이지 않았는지 한 번 더 확인한 뒤에만 올립니다.

- 자동 푸시를 끄고 싶으면 `NO_AUTOSYNC=1 ./start.sh`
- 원할 때만 올리고 싶으면 `./sync.sh` (한 번 커밋 + 푸시)
- 대기 시간을 바꾸려면 `AUTOSYNC_DEBOUNCE_MS=30000 ./start.sh`

### 데이터 자동 갱신

서버가 **30분마다** 공고 목록을 다시 받아오고, 화면은 3분마다(그리고 탭으로 돌아올 때마다) 서버 상태를 따라갑니다.
상세 정보(주택형·분양가·경쟁률)는 6시간 캐시라, 접수가 끝난 단지의 경쟁률이 공개되면 알아서 채워집니다.
주기를 바꾸려면 `AUTO_REFRESH_MINUTES=10 ./start.sh` 처럼 주면 됩니다.
상단 **새로고침** 버튼은 즉시 목록을 다시 받고, 전부 처음부터 받고 싶으면 `cache/`를 비우면 됩니다.

## 무주택 기간은 어떻게 계산되나

앱에 **생년월**만 넣으면 자동으로 계산됩니다. 규칙은 이렇습니다.

- 무주택 기간은 **본인과 배우자**만 봅니다. **만 30세가 되는 날**부터 세고, 30세 전에 혼인했다면 **혼인신고일**부터 셉니다.
- 부모님(직계존속)이 집이 있어도 **만 60세 이상**이면 그 집은 없는 것으로 봅니다.
  그러니 **부모님이 60세 되신 시점을 적는 게 아니라**, 본인 만 30세(또는 혼인신고일)부터 그대로 세면 됩니다.
- 다만 **노부모부양 특별공급**과 **LH·SH 등 공공임대**에서는 60세 이상 직계존속의 집도 **유주택으로 봅니다.**
  🏠 공공임대주택 코너의 공고는 부모님 주택 소유 여부를 따로 확인하세요.
- 본인·배우자가 집을 소유한 적이 있으면 **판 뒤 무주택이 된 날**부터 다시 셉니다 — 해당 칸에 그 날짜를 넣으세요.

청약통장도 년수 대신 **가입연월**을 넣으면 기간이 자동으로 계산됩니다.
정확한 판정은 [청약홈 가점 계산기](https://www.applyhome.co.kr/ap/apa/selectSbscrptPnttCalculationView.do)와 모집공고문을 확인하세요.

## 3. 쓰는 법

- **내 조건 설정** — 무주택 기간·청약통장 가입기간·부양가족 수를 넣으면 청약 가점(84점 만점)을 자동 계산하고,
  예산·선호 전용면적·해당하는 특별공급·관심 자치구를 저장합니다. 브라우저에만 저장됩니다.
- **맞춤도 점수(0~100)** — 예산 적합(35) + 면적 적합(15) + 관심 지역(15) + 자격·당첨 가능성(25) + 타이밍(10).
  카드 하단 칩에 점수를 준 이유가 그대로 나옵니다.
- **필터** — 진행 상태 / 공급 유형 / 자치구 / 정렬(맞춤·마감임박·최신·분양가·경쟁률), 그리고
  "내 예산 안에 드는 곳만", "내 자격 해당 특별공급만".
- **카드 클릭** — 일정 타임라인, 주택형별 분양가·평당가·예산 적합 여부, 경쟁률 표,
  당첨 가점표(내 가점과 비교해 통과/부족 표시), 공고 원문 링크.

## 데이터에 대해 알아둘 점

- 공고·일정·분양가·경쟁률·당첨가점은 모두 청약홈 원본 API 값입니다.
- **경쟁률은 접수가 끝난 뒤 공개**됩니다. 접수 중인 단지의 실시간 경쟁률은 API로 제공되지 않으므로,
  이 앱은 접수 중 단지에 대해서는 같은 자치구의 과거 커트라인을 대신 비교 기준으로 씁니다.
- 은행 전산 사정에 따라 접수건수는 사후 조정될 수 있어 청약홈 최종 수치와 다를 수 있습니다.
- 가점 계산은 주택공급규칙 별표1의 기본 산식입니다. 무주택 기간·부양가족 인정 범위 등 실제 인정 여부는
  청약홈 공식 계산기와 모집공고문을 반드시 확인하세요.

## 파일

```
server.mjs      로컬 HTTP 서버 + API 프록시 + 디스크 캐시
build.mjs       정적 사이트 빌드 (docs/ 생성) — GitHub Actions가 30분마다 실행
                --assets 를 주면 화면 코드만 복사 (API 호출 없음)
myhome.mjs      마이홈포털 통합 공고 API (SH·지방공사 포함)
scrape.mjs      SH·HUG 공개 게시판 수집 (Open API가 없는 두 기관)
notify.mjs      직전 스냅샷과 비교해 새 공고를 찾고 알림 메일 본문 생성
watch.json      이메일 알림 조건
collect.mjs     공고 수집·상세 보강 (서버와 빌드가 공유)
api.mjs         청약홈 OpenAPI 클라이언트 (분양정보 10종 / 경쟁률 8종)
lh.mjs          LH OpenAPI 클라이언트 (공고문·공급정보·상세정보)
autosync.mjs    파일 변경 감시 → 자동 커밋·푸시
sync.sh         수동 커밋·푸시
normalize.mjs   원본 레코드 → 화면용 단일 스키마
store.mjs       config.json · cache/ 관리
public/         index.html · styles.css · app.js
cache/          응답 캐시 (목록 10분, 상세 6시간) — 지워도 무방
```

## 캐시와 호출량

첫 실행 때 목록 4건 + 단지별 상세(주택형·경쟁률·가점)를 동시 4개씩 받아 `cache/`에 저장합니다.
서울 공고 100건 기준 300~400회 호출이며, 이후에는 캐시에서 즉시 뜹니다. 일 40,000건 한도에 여유가 많습니다.
"새로고침" 버튼은 공고 목록만 다시 받습니다(상세 캐시는 유지 — 빠르고 호출량이 적습니다).
30분 자동 갱신까지 합쳐도 하루 호출량은 넉넉히 한도 안입니다.
